# ADR-019 — Génération protobuf Rust autonome

## Contexte
Les schémas §5 sont le contrat inter-processus. La compilation du cœur ne doit
pas dépendre d'un `protoc` ou d'une toolchain Go installée sur la machine.

## Décision
`ske-cir/build.rs` utilise `prost-build` et le binaire fourni par
`protoc-bin-vendored`, tous deux épinglés par le workspace. Le code généré
est dans `OUT_DIR`; les schémas source, copiés littéralement, sont versionnés.
Les types CIR sont publics sous `ske_cir::proto`, les messages adaptateur sous
`ske_cir::adapter_proto`. Le script de coordination peut compiler `ske-cir`
sans générateur Go système facultatif en v0.1.

En v0.2, la génération Go utilise ce même binaire vendored, localisé par
l'exemple `protoc_path`, et `protoc-gen-go v1.36.11` dans `target/tools`.
Le script vérifie la version du générateur avant de l'utiliser. Les mappings
`M` fixent les imports Go sans modifier les schémas normatifs.

## Alternatives
`protox` éviterait un exécutable mais introduirait un autre compilateur protobuf.
Un `protoc` système rendrait les builds dépendants d'une installation cachée.
Versionner les sorties Rust créerait une deuxième source à synchroniser.

## Conséquences
Le premier build télécharge les dépendances Cargo; ensuite aucune installation
de `protoc` n'est requise. `optional bool` reste `Option<bool>`: absent signifie
effet possible, pas `false`. Les schémas évoluent de façon additive.

## Tests de non-régression
Compilation `cargo build -p ske-cir`, test `optional_effects_conservative`,
comparaison octet à octet des blocs §5 et des deux fichiers `.proto`.
En v0.2 : `./scripts/gen-proto.sh` suivi du diff des sorties versionnées,
et `go test ./internal/frame -run TestRoundTripFixtures` dans `adapters/go`.
Ce dernier compare les champs décodés en Go puis Rust et relit la réponse
Rust en Go, sans imposer l'égalité d'encodage binaire entre runtimes.
