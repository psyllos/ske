# ADR-021 — Résumés interprocéduraux : clé de cache et mode intervalles (v0.4)

## Contexte

Le §19 v0.4 impose deux choix laissés ouverts (points ★) : la clé du cache de
résumés (T-0.4-04) et l'algorithme du mode de boucle `intervals`
(T-0.4-05). Le reste du comportement est normatif : calcul par exploration de
la fonction (chaque `record_exit` = un cas, pas de fusion en v0.4), application
aux sites d'appel par substitution mémoïsée paramètres→arguments, cibles
inconnues ⇒ havoc, SCC résumés bas-en-haut, récursion à au plus
`max_recursion_unfold=2` dépliages puis un cas résiduel `PARTIAL` et une entrée
`RECURSION_BOUND` dans `unknowns`.

## Décision

### Clé de cache des résumés (§7.1, point ★ de T-0.4-04)

`summary_fingerprint = sha256_hex(
  function.structural_fingerprint |
  semantic_profile_hash |
  context_fingerprint |
  empreintes des callees triées |
  empreintes des modèles externes |
  config_fingerprint du run
)` — exactement la formule normative de §7.1, sans ajout ni omission.

Implémentation choisie (le ★ porte sur l'organisation, pas les ingrédients) :

- `structural_fingerprint` d'une fonction = hash canonique stable de sa
  définition CIR (opcodes, arité, blocs, arêtes, opérandes) calculé à
  nouveau au calcul du résumé sur les messages protobuf ordonnés et encadrés
  (fonction, types, valeurs, instructions, arêtes). La migration normative
  n'est pas modifiée : elle ne possède pas de colonne
  `functions.structural_fingerprint`. Il ne dépend pas des résumés des callees.
- `context_fingerprint` = fingerprint du contexte applicatif (répertoire
  `context_fingerprint` sur `function_summaries`), déjà prévu par le schéma.
- `config_fingerprint` du run : le hash de configuration déjà produit à
  l'ouverture d'un run d'analyse (budget canonique + snapshot + contexte +
  version, cf. `ske-query`).
- Les empreintes des callees triées : on calcule les résumés des callees
  avant le resume du parent (SCC bottom-up), puis on concatène leurs
  `summary_fingerprint` triés lexicographiquement. Pour une fonction
  récursive, les dépliages successifs portent des empreintes différentes car
  le corps substitué change ; le cas résiduel `PARTIAL` (havoc `H`) a une
  empreinte distincte de chaque dépliage.
- `models_fingerprint` : en v0.4 les effets externes non modélisés sont
  `UNKNOWN_EFFECT` (§7.3) ; la liste canonique des empreintes des modèles
  est vide tant qu'aucun modèle n'est chargé. Les frontières des champs sont
  conservées par sérialisation JSON canonique avant SHA-256.

La clé ainsi définie garantit : deux calculs identiques (mêmes sources, mêmes
callees, même config) produisent exactement la même empreinte (AC-0.4-13).

### Mode de boucle `intervals` (point ★ de T-0.4-05)

Algorithme concret retenu, conforme au texte normatif de §19 v0.4 :

1. Se déclenche à la `(loop_unroll+1)`ᵉ arrivée d'un en-tête de boucle par
   l'arête de retour (le comptage suit l'arête de retour spécifique de la
   boucle, comme en mode `unroll`).
2. `ske-abstract` fournit le domaine : intervalles entiers bornés par type
   (signed/unsigned, largeur ≤ 128), transfert `ADD`/`SUB`/`MUL` avec
   détection de débordement ⇒ plage complète du type, itération de Kleene
   avec élargissement (borne instable ⇒ borne du type) puis **un** pas de
   rétrécissement.
3. Collecter dans la boucle les valeurs entières modifiées (dont les PHI de
   l'en-tête) et calculer leurs intervalles. Toute adresse écrite dans la
   boucle est havockée.
4. État générique : chaque PHI d'en-tête dont l'entrée de retour diffère de
   l'entrée d'en-tête devient un symbole frais `loopvar:<phi>` contraint
   (ajouté aux contraintes du chemin) à son intervalle. Soundness de l'état =
   `OVERAPPROX`.
5. Explorer cet état générique **une fois** ; un en-tête déjà vu avec
   `abstracted=true` est abandonné (subsumption). Aucune coupure n'est
   comptée pour cette boucle (l'exploration peut être fermée).
6. Ajouter l'hypothèse `LOOP_INTERVAL_ABSTRACTION` et émettre le diagnostic
   `LOOP_ABSTRACTED` (INFO, producteur `ske-abstract`). Les
   `PROVEN_UNREACHABLE` ainsi obtenus portent `soundness=OVERAPPROX` et, côté
   règles, `origin=ABSTRACT_DERIVED`.

Le mode par défaut reste `unroll` (comportement v0.3 inchangé) ; `intervals`
n'est activé que par `loop_mode = "intervals"` dans `budget.toml`.

## Alternatives

- Résumer par points fixes itératifs complets : plus précis mais coûteux et
  hors périmètre v0.4 (rejeté pour ce jalon).
- Ne pas matérialiser `loopvar:` et garder les PHI symboliques sans intervalle
  : perd la preuve d'inaccessibilité fermée et l'overapproximation annoncée
  (rejeté).
- Mode `intervals` sans diagnostic ni hypothèse : casserait le registre et
  la traçabilité des assumptions (rejeté).

## Conséquences

- `ske-symbolic` dépend de `ske-abstract` (whitelist déjà à jour, §2.2).
- Les tables du schéma normatif deviennent réellement utilisées :
  `function_summaries` et ses enfants ; aucune migration supplémentaire ne
  modifie `0001_initial.sql`.
- Les résumés `EXACT` ne sont proclamés que sous les hypothèses explicites du
  run ; les cas `PARTIAL`/`OVERAPPROX` conservent leurs limites (aucune fausse
  conclusion de certitude).

## Tests de non-régression

- `summary_deterministic` : deux calculs ⇒ même `summary_fingerprint`.
- `summary_fact` : 4 cas, 1 `PARTIAL`, `complete=0`, `RECURSION_BOUND`.
- `analysis_sum_intervals` : `Sum` en mode `intervals` ⇒ `COMPLETED`,
  `exploration_closed=true`, ENTER_BODY/EXIT `POSSIBLE`, aucun `PU`,
  diagnostic `LOOP_ABSTRACTED` ; les `analysis_*` de v0.3 restent `PASS` en
  mode `unroll` (AC-0.4-11).
- `cargo test -p ske-abstract` (AC-0.4-09), `summary_matches_concrete`
  (AC-0.4-08).
